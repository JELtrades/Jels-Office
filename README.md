# Jaden's Virtual Office — Public (GitHub Pages) Version

A bookmarkable, live-in-the-browser version of Jaden's Virtual Office: nine
animated bots (Scanner, Paper, Bell, George, Frank, Muse, and Rob, Jane, Clip 3)
across four rooms — trading, the shop, Muse's office at the end of the
hallway, and the clipping room at the back — with Working / Waiting /
Needs-you badges and an office log. It mirrors the in-app Virtual Office,
but it is a plain static site — it opens from any browser via a normal URL
and stays live.

## Files

| File | What it is |
| --- | --- |
| `index.html` | The whole office. Single self-contained page (HTML + CSS + JS, no build step, no server). Fetches `status.json` on load and re-fetches it every **5 minutes**, updating badges, speech bubbles, and the log without a reload. Also has a **Refresh now** button, a visible "Last updated" stamp, and a next-refresh countdown. |
| `status.json` | The current snapshot, generated by `generate_status.py`. The page reads this file — it never talks to the logs directly. |
| `generate_status.py` | Reads Jaden's real logs/state files on this machine and writes `status.json`. Run it with `python3 generate_status.py`. |
| `README.md` | This file. |

## How the 5-minute refresh works (two halves)

1. **Browser half (automatic):** `index.html` calls `fetch("status.json?ts=...")`
   on load and then every 5 minutes (`setInterval(fetchStatus, 5*60*1000)`),
   with a cache-buster so GitHub Pages never serves a stale copy. Badges,
   bubbles, and the log update in place — no page reload.
2. **Data half (needs a scheduled push):** `status.json` on GitHub Pages only
   changes when someone pushes a new copy. The page re-fetching every 5
   minutes is useless unless the file itself is refreshed. So this machine
   must re-run `generate_status.py` and `git push` the new `status.json`
   every 5 minutes. See "Keeping it live" below.

## How statuses are derived (no faked activity)

`generate_status.py` reads the real sources and derives each status from
that bot's real schedule against the current America/New_York time:

- **Scanner / Paper — working** only Mon–Fri 09:30–14:00 ET (the JELS
  paper-trading window: opens 09:30–10:30 + midday 11:00–12:00, engine
  polling every 5 min). Otherwise **waiting**. Last action comes from
  `ict-paper-state.json` (latest trade, engine run count).
- **Newswire — working** only when its last Trump sweep (from
  `reported.json`) is less than 45 minutes old; sweeps run every 30 min
  around the clock. Otherwise **waiting**.
- **Bell — working** only within 45 minutes after a scheduled reminder
  (Mon–Fri 7:00 AM ET NY, Sun–Thu 5:00 PM ET Asia). Otherwise **waiting**.
- **Keeper — waiting** until the Grind & Gather launch (Black Fri Nov 27,
  2026) at Jaden's call; his launch items (social handles, store password
  + test order) stay recorded and surface as **needs-you** again on/after
  Nov 27. **Ledger — needs-you** while real recorded decisions are open:
  11 trade sessions unlogged, weekly review Fri Nov 13 5:45 PM ET. These
  flip to waiting / working only when Jaden actually resolves them — the
  script does not invent activity.

Sources read (never written): `goals/trading-session-reminders/hidden_files/ict-paper-state.json`,
`goals/trump-statement-market-alerts/hidden_files/reported.json`,
`goals/trade-journal/files/trade-journal.md`, plus dated facts recorded in
`~/MEMORY.md` (store events, reminder deliveries).

## Remaining step — publish it (needs Jaden)

Nothing has been pushed anywhere and no GitHub account or repo has been
created — that step needs Jaden's email verification, so it is his to do
(or to approve). Exact steps:

1. **Create a free GitHub account** at https://github.com/signup (needs
   Jaden's email + verification). If he already has one, use it.
2. **Create a new public repository**, e.g. `virtual-office` (public, no
   README/gitignore/license needed — the files are already here).
3. **Enable GitHub Pages:** repo → Settings → Pages → Source: "Deploy from
   a branch", Branch: `main`, Folder: `/ (root)` → Save. The site will be
   live at `https://<username>.github.io/virtual-office/` within a minute
   or two. **Bookmark that URL.**
4. **Push these files** from this machine (once, to start):
   ```bash
   cd ~/workspace/virtual-office-public
   git init
   git add index.html status.json generate_status.py README.md
   git commit -m "Virtual Office public site"
   git branch -M main
   git remote add origin https://github.com/<username>/virtual-office.git
   git push -u origin main
   ```
   (GitHub will ask for sign-in on push — use a personal access token as
   the password, or GitHub CLI `gh auth login`.)
5. **Keeping it live (the 5-minute data push):** after the repo exists,
   add a cron on this machine that regenerates + pushes `status.json`
   every 5 minutes:
   ```bash
   */5 * * * * cd ~/workspace/virtual-office-public && python3 generate_status.py && git add status.json && git commit -m "status update" --allow-empty && git push -q
   ```
   That is what makes the bookmarked page actually stay current. Without
   it, the page still loads and refreshes, but the data freezes at the
   last push.

## Privacy note

This page is **public by design** once published on GitHub Pages — anyone
with the link can see it. It contains only trading/store status summaries
(no account numbers, no addresses, no dollar balances beyond the paper
trade's hypothetical points and the Lucid buffer totals already shown in
the in-app office). If Jaden ever wants it private, GitHub Pages on a free
account cannot do that — the page would need to come down or move to a
private host.
